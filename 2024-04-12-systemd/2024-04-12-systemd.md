## systemd

`systemd` 는 Linux 운영체제의 부팅 및 서비스 관리에 사용하는 시스템 관리 도구입니다. 1번 PID 를 가지며, 기존에 사용하는 `init` 를 대체합니다. 서비스를 시작, 중지, 재시작, 감시 및 로그 기록등 관리 작업을 수행합니다. RHEL, CentOS, Ubuntu 등 대부분의 Linux 시스템에서 사용합니다.

작업은 Unit 단위로 구분하며, 아래와 같은 유형을 가지고 있습니다. 이 글에서는 가장 많이 사용하는 'Service' 를 대상으로 합니다.

| Unit      | 확장자     | 설명                                   |
|:---------:|:----------:|:---------------------------------------|
| Service   | .service   | 시스템 서비스                          |
| Target    | .target    | init 프로세스의 run-level 과 맵핑      |
| Automount | .automount | 파일 시스템 자동 마운트 지점           |
| Device    | .device    | 커널에서 인식한 장치 파일              |
| Mount     | .mount     | 파일 시스템 파운트 지점                |
| Scope     | .scope     | 외부에서 생성하고 관리하는 프로세스    |
| Slice     | .slice     | 프로세스 그룹의 자원을 계층적으로 관리 |
| Snapshot  | .snapshot  | 특정 시점의 모든 Unit 의 상태를 저장   |
| Socket    | .socket    | 프로세스간 통신 소켓                   |
| Swap      | .swap      | 특정 파일 시스템이나 디렉토리 모니터링 |
| Timer     | .timer     | crontab 과 같이 일정 주기마다 실행     |

## 실행 파일 생성

`systemd` 서비스에서 사용할 실행 파일을 작성합니다. `count.sh` 는 매 초 마다 1씩 증가하여 출력합니다.

``bash filename=count.sh
#!/usr/bin/env bash
COUNT=0
while [ 1 ];
do
  COUNT=$((COUNT+1));
  echo "count: $COUNT";
  sleep 1;
done;
``

실행 가능하도록 mode 를 변경합니다.

```bash
$ chmod +x count.sh
```

## Unit 파일 생성하기

Unit 은 `systemd` 에서 실행할 방법을 기술한 파일 입니다. 서비스로 동작하기 때문에 `.service` 확장자로 끝나는 파일을 작성합니다.

```bash filename=/etc/systemd/system/count.service
[Unit]
Description=Count Service

[Service]
ExecStart=/path/to/count.sh

[Install]
Wantedy=multi-user.target
```

`Unit` 섹션에서는 Unit 에 대한 설명과, 다른 Unit 과의 관계를 설정할 수 있습니다.

- Description: Unit 에 대한 설명
- Documentation: Unit 에 대한 문서 경로
- After: 현재 Unit 보다 먼저 실행해야 할 Unit
- Before: 현재 Unit 이후에 실행해야 할 Unit
- Requires: 현재 Unit 이 의존성을 가지는 Unit
- Wants: Requires 와는 유사하지만, 실패하더라도 현재 Unit 을 실행
- BindsTo: Requires 와는 유사하지만, 이 Unit 이 종료되면 같이 종료함

`Service` 섹션에서는 Unit 을 실행, 종료 등에 필요한 명령을 설정합니다.

- Type: 서비스의 동작 방식을 설정 (기본값: simple)
  - simple: 일반적인 프로세스에서 사용 
  - forking: 서비스가 자식 프로세스를 생성할 때 사용
  - oneshot
  - dbus
  - notify
  - idle
- ExecStart: 실행할 명령을 지정
- ExecStop: 종료할 명령을 지정 
- ExecStartPre: 서비스를 시작하기 전 명령을 지정
- ExecStopPre: 서비스를 종료하기 전 명령을 지정
- Restart: 재시작 명령을 지정
- TimeoutSec: 
- User
- Group

`Install` 섹션에서는 서비스를 enable 또는 disable 할 때, 동작 방식을 설정합니다.

- WantedBy:
- Also:
- Alias:

## 서비스의 관리

서비스에 변경 사항이 발생한 경우 `daemon-reload` 명령을 실행합니다.

```bash
$ sudo systemctl daemon-reload
```

'start' 명령으로 서비스를 실행합니다.

```bash
$ sudo systemctl start count
```

'stop' 명령으로 서비스를 종료합니다.

```bash
$ sudo systemctl stop count
```

`restart` 명령으로 서버를 재시작합니다.

```bash
$ sudo systemctl restart count
```

'enable' 명령은 부팅시에 서비스를 실행하도록 합니다. 반대로 실행하지 않도록 하려면 'disable' 명령을 사용합니다.

```bash
$ sudo systemctl enable count
$ sudo systemctl disable count
```
